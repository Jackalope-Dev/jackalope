# Jackalope 0.1.35

Status: ready
Date: 2026-11-15

## Highlights

- **Follow pull requests from the work list.** After a task opens a pull request,
  Jackalope keeps watching it. The list and board show whether it is waiting on
  checks or review, needs a fix or is ready to merge, and you get a notification
  when that changes. One click drafts the fix for failed checks, review comments
  or a conflict for the task's own agent. Pushing the update and merging each ask
  first.
- **A cleaner, guided Jackalope.** Settings are regrouped so things are easier to
  find, project settings live on each project with a How hands-on? preset, and
  setup screens guide you step by step with a live diagram of what is connected.
  The sidebar starts with an Inbox of what needs you.
- **A board with real lanes.** Needs you, Working, In review, Drafts and Finished
  sit side by side, and every row says why it needs you, such as a failed check
  or a waiting question.
- **Pick up terminal conversations.** Claude Code and Codex conversations you had
  in a terminal or another app appear under their project. Open one to read it,
  or continue it in Jackalope in the same checkout. Nothing is uploaded, and
  Settings → Privacy turns it off.
- **Resume work Jackalope closed in the middle of.** Work that was running when
  Jackalope closed or restarted has a Resume button that continues the agent's
  conversation in the same workspace.

## Improvements

- Useful settings now start on: finished work is checked with your project's
  check command, your computer stays awake while agents work, a learning step
  reflects on finished work with your default agent (a few short calls a day on
  that account), stopped terminal output is restored and updates download in the
  background. Each can be turned off in Settings or Project settings.
- Add agent lists known ACP agents by name, such as Cursor, GitHub Copilot CLI,
  Goose and Qwen Code, and fills in the ones installed on your computer.
- Share a project's bots as one file, and import a shared file after reviewing
  it. Imported bots start with no connections and their wake-ups off.
- Replies can be read aloud, a conversation can be copied as Markdown, and bots
  have a right-click menu with Mark as read and Mark as unread.
- Project setup explains each step, and the project overview gives the same
  reason a task needs you as the work list does.
- Agents waste less time on long runs: they can stop a process they started
  without asking, a late answer reaches the agent with its next step, and a
  missing Mac permission names the setting to open.
- Failed attempts say what kind of failure it was, such as sign-in, quota or an
  unavailable model, with a next step. A different model than the one you asked
  for is shown on the attempt.
- Secret values given to an agent are removed from the attempt's saved record.
- Bots have a new gallery, schedules use one When picker, and the phone app has a
  new look and shows offline computers.
- Text on task, settings and other workspace pages can be selected and copied.

## Fixes

- Primary buttons, including Connect account, no longer show a faint, hard to
  read label in installed builds.
- A continuation whose agent session is gone is reported and starts once as a
  new conversation, instead of answering as if it had resumed.
- Check results automatically now reads the same in Project settings as it
  behaves when you start work.
- A used-up Claude window is reported as out of quota.
- Each model is sent only an effort level it accepts.

## Known issues

- Followed pull requests, the ACP agent list, bot sharing and reading replies
  aloud are new in this beta and have not yet been accepted in an installed app.
  The ACP agents in the list have not each been run through Jackalope.
- If you turned Check results automatically off by never setting it, it is now
  on; turn it off in Project settings if you do not want checks to run.
- The phone companion is not in the App Store or Play Store yet. Installed phone
  builds pair only over HTTPS, such as a Tailscale address.
- Desktop control on Wayland needs a desktop that offers the remote desktop
  portal.
- Signed installation and updates still need validation on each platform.
